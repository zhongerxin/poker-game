# Widget 快捷下注

实现及生产发布日期：2026-09-30。已部署现有 `poker-game` Worker 和静态资源至 <https://poker-api.jiqiren.ai>，无需发布新的插件版本。

生产版本：`3fbd1eb4-c81f-4d3e-a683-333a98fcbe50`，承接 100% 流量。线上首页与本地生产构建逐字节一致，包含英文下注指令及展开收起动画。

## 交互

保留原有绿色牌桌、牌面、头像和筹码布局。下注按钮使用与筹码面板相同的深绿色，整个操作区与面板同宽（17rem）。上排是等宽的 `Fold` / `Call`，下排是宽版 `Raise <金额>` / `↑`，不展示标题或常驻说明。

- `Fold` / `Call` / `Raise` 点击后提交行动。`Call` 没有待跟金额时按过牌处理；不显示服务端无法实时确认的跟注数值。
- 下注指令和牌局上下文说明统一以英文发送，不随宿主或浏览器语言切换。
- `↑` 展开自定义加注：滑杆选择整数筹码，箭头确认发送，`×` 收起。预设按钮也采用两行排列，并保持与面板同宽。
- `1 BB` 将当前选择增加一个大盲；`1/2 Pot` / `Pot` 按当前显示底池选择金额。这些快捷键只选值，不立即发送。
- 滑杆上限为该轮有效筹码；翻牌前的「加注到」包含已下盲注。滑到最右选择最大有效投入，短筹码可以选择唯一可用的全下额度。
- 发送中及成功后锁定按钮；对手同阶段再次行动后，可点右侧回转箭头恢复。换手或换阶段自动恢复。发送失败可重试。
- 筹码耗尽时禁用；摊牌或缺少上下文的旧结果不显示操作。消息仍通过现有 `window.openai.sendFollowUpMessage` 交给 AI 对手处理，也可继续在聊天里输入。

目前服务端不记录轮内每次加注。滑杆提供基于该街起始状态的数额选择，最新最小合法加注由模型结合对话校验；若所选数额已经不合法，提示重新选择，不能擅自改金额。不会从按钮直接调用发牌或结算工具。

工具结果提供 `game_id`、`hand_id`、`stage`、盲注和庄位供界面使用，不修改发布的工具接口。旧 widget 的上下文仍由模型检查，不是服务端实现的轮内状态校验。

## 本地预览

```bash
npm run dev:widget
```

打开 <http://127.0.0.1:5173/test/fixtures/widget-host.html?widget=table>。该入口使用模拟宿主，只记录按钮发送的消息，不连接线上服务，不产生真实牌局或分析事件。默认是无调试文字的纯界面；在 URL 添加 `&debug=1` 可打开控制台，切换阶段、中英文、无筹码、已结算、旧数据、新版宿主数据格式及不支持消息的场景，也可以模拟发送失败、保存失败和新一手。

预览配置不加载 Cloudflare 插件，避免本地查看 UI 依赖 Cloudflare 登录或网络。`test/fixtures` 没有被生产入口引用，不进入 `dist/client`。

## 上线方式

**本次只需构建并部署现有 Worker 及静态资源，无需发布新的插件版本。** 理由是工具名称、描述、参数 schema、工具元数据、资源 URI、CSP 和域名均未改变；只增加兼容的工具返回数据并更新相同 URI 下的 widget 内容。

依据 [OpenAI 官方维护说明](https://developers.openai.com/plugins/deploy/app-review#other-changes)，相同已发布 UI URI 的兼容内容更新，以及保持契约兼容的服务端结果（含结果 `_meta`）修改，部署即可，不需要重新扫描、提交或发布版本。ChatGPT 可能缓存 UI 内容最长一小时，已经打开的旧界面不会自动热更新。部署后应新生成牌桌验证；不要为了强制刷新而随意更换已发布 URI。

后续若修改插件资料或随插件提交的 skills，需要走新版本审核；工具定义、工具 `_meta`、UI 资源引用或 CSP 变更依当前文档由持续审核处理，未通过前须兼容旧定义。本次不依赖这些更新。

消息桥接与工具结果格式参考：[window.openai 官方说明](https://developers.openai.com/plugins/reference#windowopenai-component-bridge)。
